# Copyright & License (REUSE) Skill

Use this skill to create or fix REUSE.toml files for any repository to achieve REUSE 3.3 spec compliance.

## Source of Truth: MANIFEST.toml

Before doing anything else, check whether a `MANIFEST.toml` file exists in the repository root.

If `MANIFEST.toml` exists:
- Use it as the authoritative source of copyright and license information for every file. Do not re-scan file headers yourself.
- Read the `[[annotations]]` entries. Each entry has a `path`, `SPDX-FileCopyrightText`, and `SPDX-License-Identifier`.
- Entries with `# MISSING: copyright` or `# MISSING: license` comments, or empty string values, indicate files with incomplete information. Treat these the same as files with no license information (see that section below).
- Entries with `# AMBIGUOUS LICENSE:` comments indicate free-form license text that could not be mapped to an SPDX identifier. Ask the user to confirm the correct SPDX ID before proceeding.
- `MANIFEST.toml` is generated by `reuse-manifest.py`. If it is stale or missing, suggest the user run: `python3 reuse-manifest.py -i . --create`

If `MANIFEST.toml` does not exist:
- Fall back to reading file headers directly (see "Reading Files" below).
- Suggest the user generate a manifest first for better accuracy on large repos.

## Before Writing Anything

Ask the user:
- What is the default copyright holder and year for unheadered files?
- What is the default license for files with no license header?

Never guess these values.

## Reading Files (fallback when no MANIFEST.toml)

- Read the actual license header of every file before assigning any SPDX identifier.
- Never infer the license from the copyright holder, file type, or directory name.
- When the license text is ambiguous, look it up on spdx.org/licenses/ before assigning an identifier.
- When still in doubt, ask the user.

## REUSE.toml Rules

- Never add `.license` sidecar files beside source files. Use only REUSE.toml for annotations.
- Keep REUSE.toml as short as possible. Use directory globs (`src/**`) when all files in a directory share the same license.
- Use section header comments (`# --------`) to group annotations. Do not use single-line inline comments.
- In REUSE.toml, later annotations override earlier ones for the same file. Put broad catch-all rules first, specific overrides after.
- TOML does not allow duplicate keys. Use arrays for multiple copyright holders:
  ```toml
  SPDX-FileCopyrightText = ["2024 Alice", "2024 Bob"]
  ```
- Every file in the repository must have both copyright and license information. Zero exceptions.

## LICENSES/ Directory

- Use `reuse download <SPDX-ID>` to obtain official license texts. Do not write license texts manually.
- Only use `LicenseRef-` custom identifiers when no official SPDX identifier exists. Always check spdx.org/licenses/ first.
- Never delete a file from `LICENSES/` without first confirming it is unused — `reuse lint` will flag unused licenses.

## Validation

- Run `reuse lint` after every change.
- Iterate until the output shows full REUSE 3.3 compliance with zero errors.
- All 100% of files must have copyright and license information before the task is complete.
- All licenses and copyright in files must match what is in REUSE.toml

## Handling Files With No License Information

When a file has no license or copyright header and its provenance is not obvious:

1. Ask the user per file what SPDX annotation to use. Ask one file at a time.
2. Regardless of the user's answer, always add that file to `LICENSE_EXCEPTIONS.md` in the root of the repository.
3. `LICENSE_EXCEPTIONS.md` must record for each file:
   - Use a `## License Exceptions` main heading (not `#`).
   - The file or list of files must appear in backticks (e.g. `` `path/to/file` ``), not as a `##` section heading.
   - Two bullet points per entry: the chosen SPDX annotation (license + copyright), and the rationale for that choice.
   - No "open question" or "action required" bullet point.
4. The goal of `LICENSE_EXCEPTIONS.md` is to give project maintainers a ready-made checklist to follow up with upstream authors before treating the annotations as final.

## Anti-patterns

- Never change any files in the repository except REUSE.toml, LICENSES/, and LICENSE_EXCEPTIONS.md.
- Never guess a license or copyright holder — always verify from file content or ask the user.
- Never batch-ask about multiple ambiguous files in a single question — ask one file at a time.
